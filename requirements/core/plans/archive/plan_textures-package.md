# @brewsite/textures — PBR Material Preset Package

## Summary

Create a new `@brewsite/textures` package that ships KTX2-compressed PBR material presets (onyx, marble, steel, copper, gold, brushed-steel, etc.) alongside a shared material loader, triplanar CSM shader helper, and a Vite plugin for static-site deployment. Every widget in core, diagram, charts, and screens that uses `MeshStandardMaterial` or `MeshPhysicalMaterial` gains access to named material presets through the `WidgetRegistry`, with per-widget application controls (colorMix, brightness, saturation, depthMix, iridescence, etc.) that are animatable through the transition system.

---

## Phase 0 — Foundation Types & Loader in `@brewsite/core`

All types and the shared loader live in core so that every downstream package can consume materials without depending on `@brewsite/textures` directly.

### 0.1 — Material Types

**File: `packages/core/src/widget/materialTypes.ts`**

```typescript
// Material preset and application types — shared across all packages.

/**
 * Texture map URLs for a single PBR material preset.
 * All URLs point to .ktx2 files served from the consumer's static directory.
 * Paths are relative to a configured basePath (e.g. '/assets/materials').
 */
export type MaterialPresetMaps = {
  readonly color: string;
  readonly normal: string;
  readonly roughness: string;
  readonly metalness?: string;
  readonly displacement?: string;
};

/**
 * PBR parameter defaults that accompany a material preset.
 * Applied when the material is loaded; overridden by widget-specific style props.
 */
export type MaterialPresetDefaults = {
  readonly metalness: number;
  readonly roughness: number;
};

/**
 * A named material preset: texture URLs + PBR defaults.
 * Resolved from the MaterialManifest at runtime.
 */
export type MaterialPreset = {
  readonly maps: MaterialPresetMaps;
  readonly defaults: MaterialPresetDefaults;
};

/**
 * Manifest mapping preset names to their texture URLs and defaults.
 * Generated by the @brewsite/textures package and registered on
 * WidgetRegistry via texturesPlugin().
 */
export type MaterialManifest = {
  readonly version: number;
  readonly basePath: string;
  readonly presets: Readonly<Record<string, MaterialPreset>>;
};

/**
 * Controls how a material preset's textures are applied to a surface.
 *
 * These are application-time knobs — they modify how the preset's raw
 * textures blend onto the geometry, not the textures themselves. The same
 * 'onyx' preset can look subtle (low colorMix, desaturated) behind text
 * or vivid (full colorMix, saturated) on an empty floor.
 *
 * All values default to "full strength, no adjustment" when omitted.
 * All numeric values are uniform-only updates — O(1), no GPU recompile,
 * safe to call every frame, animatable through the transition system.
 */
export type MaterialApplication = {
  /**
   * How much the texture color replaces the base color [0-1].
   * 0 = pure base color (texture invisible). 1 = pure texture color.
   * Primary readability dial — lower when text sits on the surface.
   * @default 1.0
   */
  readonly colorMix?: number;

  /**
   * Texture brightness multiplier [0-2+].
   * 1.0 = unchanged. <1 = darker. >1 = brighter.
   * @default 1.0
   */
  readonly brightness?: number;

  /**
   * Texture saturation multiplier [0-2+].
   * 0 = fully desaturated (grayscale). 1.0 = unchanged. >1 = oversaturated.
   * @default 1.0
   */
  readonly saturation?: number;

  /**
   * Texture contrast adjustment [-1 to 1].
   * 0 = unchanged. >0 = more contrast. <0 = flatter/washed out.
   * @default 0
   */
  readonly contrast?: number;

  /**
   * How much the texture's normal/bump detail shows [0-1].
   * 0 = flat surface (no depth). 1 = full depth detail.
   * @default 1.0
   */
  readonly depthMix?: number;

  /**
   * How much the texture's roughness map overrides base roughness [0-1].
   * 0 = uniform base roughness. 1 = full texture roughness variation.
   * @default 1.0
   */
  readonly roughnessMix?: number;

  /**
   * Tint color multiplied into the texture color before mixing.
   * Colorize neutral stone/metal to match a brand palette.
   * @default undefined (no tint)
   */
  readonly tint?: string;

  /**
   * Texture coordinate scale override. Larger = fewer repeats (zoomed in).
   * @default undefined (use preset default, typically 0.12)
   */
  readonly texScale?: number;

  /**
   * Thin-film iridescence strength [0-1].
   * Simulates oil-slick / anodized metal / pearl sheen.
   * Auto-upgrades CSM base to MeshPhysicalMaterial when > 0.
   * @default 0
   */
  readonly iridescence?: number;

  /**
   * Iridescence film refractive index [1.0-2.33].
   * Lower = broad soft shifts (soap bubble). Higher = tight vivid bands (bismuth).
   * @default 1.3
   */
  readonly iridescenceIOR?: number;

  /**
   * Thin-film thickness range in nanometers [min, max].
   * Controls which colors appear. [100,200]=cool blues. [200,400]=full rainbow. [300,500]=warm golds.
   * @default [100, 400]
   */
  readonly iridescenceThicknessRange?: readonly [number, number];
};

/**
 * Loaded texture set — Three.js Texture objects ready to apply.
 * Returned by MaterialLoader.loadPreset().
 */
export type LoadedMaterialTextures = {
  readonly color: import('three').Texture;
  readonly normal: import('three').Texture;
  readonly roughness: import('three').Texture;
  readonly metalness?: import('three').Texture;
  readonly displacement?: import('three').Texture;
};

/**
 * Resolved preset with loaded GPU textures + PBR defaults.
 */
export type LoadedMaterialPreset = {
  readonly textures: LoadedMaterialTextures;
  readonly defaults: MaterialPresetDefaults;
};
```

**Dependency:** None (types only — no Three.js, no React imports in the type file).

### 0.2 — MaterialLoader

**File: `packages/core/src/widget/MaterialLoader.ts`**

Shared KTX2 texture cache and loader. One instance per `WidgetRegistry`. All widgets in all packages share the same texture cache — if the carousel tray and the floor both use `'onyx'`, the textures load once.

```
Responsibilities:
- Initialize KTX2Loader with renderer + transcoder path
- Load MaterialPreset → LoadedMaterialPreset (cached by URL)
- Resolve relative paths against MaterialManifest.basePath
- Dispose all cached textures on teardown
```

Key implementation details:

- **Cache by full resolved URL** — not by preset name. If two presets share the same roughness texture, it loads once.
- **Return `Promise<LoadedMaterialPreset>`** — widgets call this in apply() and cache the result. The promise resolves immediately on cache hit.
- **KTX2Loader is per-renderer** — use the existing `WeakMap<WebGLRenderer, KTX2Loader>` pattern from `ModelRenderer`.
- **transcoderPath defaults to `'/assets/materials/basis/'`** — configurable via `texturesPlugin()` options.
- **Textures are `RepeatWrapping` + linear filtering** by default. Color map gets `SRGBColorSpace`; normal/roughness/displacement stay linear.

```typescript
// Signature sketch:
export class MaterialLoader {
  initialize(renderer: THREE.WebGLRenderer, transcoderPath?: string): void;
  loadPreset(preset: MaterialPreset, basePath: string): Promise<LoadedMaterialPreset>;
  getLoadedPreset(presetName: string): LoadedMaterialPreset | null;  // sync cache hit
  dispose(): void;
  disposeForRenderer(renderer: THREE.WebGLRenderer): void;
}
```

**Dependency:** `three` (KTX2Loader, Texture, WebGLRenderer).

## Phase 1 — CSM Material Factory in `@brewsite/core`

> **Note:** `packages/core/src/elements/_shared/` is a **new directory** — it does not exist yet. Create it as part of this phase.

**File: `packages/core/src/elements/_shared/materialFactory.ts`**

Single CSM-based material factory that supports both triplanar and standard-UV projection. All `MaterialApplication` controls are exposed as uniforms — O(1) per-frame updates, no GPU recompile, fully animatable through the transition system.

The factory takes a `projection: 'triplanar' | 'uv'` parameter:
- **`'triplanar'`** — For extruded/irregular geometry without clean UVs (carousel tray, chart bars, bezels). Vertex shader passes object-space position + normal; fragment samples all maps using triplanar blending.
- **`'uv'`** — For flat geometry with clean UVs (floor plane, diagram nodes/groups). Vertex shader uses default UVs; fragment samples maps using `vUv`. Same application-control uniforms as triplanar.

Both paths use `CustomShaderMaterial` (CSM). There is no `onBeforeCompile` path — CSM provides uniform-based updates for both projection modes.

### GLSL Shaders

**Triplanar vertex shader** (`projection: 'triplanar'`):

```glsl
varying vec3 v_objPos;
varying vec3 v_objNormal;
void main() {
  v_objPos = position;
  v_objNormal = normal;
}
```

**UV vertex shader** (`projection: 'uv'`):

```glsl
// No custom vertex shader needed — uses default CSM UV passthrough (vUv).
```

**Fragment shader (shared application controls, projection-specific sampling):**

Both projection modes share the same application-control uniforms and color pipeline. The only difference is how texture coordinates are computed:
- **Triplanar:** `pow(abs(normal), vec3(4.0))` blending weights from `v_objPos` / `v_objNormal`.
- **UV:** Direct `vUv` sampling.

Uniforms:

| Uniform | Type | Source |
|---|---|---|
| `u_colorMap` | `sampler2D` | `textures.color` |
| `u_normalMap` | `sampler2D` | `textures.normal` |
| `u_roughnessMap` | `sampler2D` | `textures.roughness` |
| `u_displacementMap` | `sampler2D` | `textures.displacement` (or blank) |
| `u_texScale` | `float` | `application.texScale ?? presetDefault` |
| `u_colorMix` | `float` | `application.colorMix ?? 1.0` |
| `u_brightness` | `float` | `application.brightness ?? 1.0` |
| `u_saturation` | `float` | `application.saturation ?? 1.0` |
| `u_contrast` | `float` | `application.contrast ?? 0.0` |
| `u_depthMix` | `float` | `application.depthMix ?? 1.0` |
| `u_roughnessMix` | `float` | `application.roughnessMix ?? 1.0` |
| `u_tint` | `vec3` | `application.tint ?? (1,1,1)` |
| `u_normalStrength` | `float` | `0.5 * depthMix` |
| `u_bumpStrength` | `float` | `0.02 * depthMix` |

Fragment logic (in order):

1. **Triplanar sample** all maps using `pow(abs(normal), vec3(4.0))` blending weights.
2. **Color pipeline:** `texColor = triplanarSample(u_colorMap)` → `*= u_tint` → `adjustSaturation(u_saturation)` → `adjustContrast(u_contrast)` → `*= u_brightness` → `csm_DiffuseColor = mix(csm_DiffuseColor.rgb, texColor, u_colorMix)`.
3. **Roughness:** `csm_Roughness = mix(csm_Roughness, triplanarSample(u_roughnessMap).r, u_roughnessMix)`.
4. **Normal:** Triplanar world-space normal blend → `csm_FragNormal = mix(geomNormal, texNormal, u_depthMix * u_normalStrength)`.
5. **Bump:** `csm_Bump = triplanarSample(u_displacementMap).r * u_depthMix * u_bumpStrength`.

### TypeScript API

```typescript
export type PresetMaterialProjection = 'triplanar' | 'uv';

export type PresetMaterialOptions = {
  textures: LoadedMaterialTextures;
  defaults: MaterialPresetDefaults;
  /** Texture projection mode. 'triplanar' for extruded geometry, 'uv' for flat/clean-UV geometry. */
  projection: PresetMaterialProjection;
  application?: MaterialApplication;
  baseColor?: string;
  baseOpacity?: number;
};

/**
 * Creates a CSM material with the specified projection mode and all
 * MaterialApplication controls as uniforms.
 *
 * Both projection modes use CustomShaderMaterial — the only difference is
 * the vertex/fragment GLSL for texture coordinate computation.
 */
export function createPresetMaterial(options: PresetMaterialOptions): CustomShaderMaterial;

/**
 * Updates application-time controls on an existing preset material.
 * Uniform-only — O(1), no GPU recompile, safe every frame, animatable.
 * Works identically for both projection modes.
 */
export function applyMaterialApplication(
  material: CustomShaderMaterial,
  application: MaterialApplication,
  baseColor?: string,
): void;

/**
 * Swaps the texture set on an existing preset material.
 * Use when the preset name changes but the geometry hasn't.
 * Works identically for both projection modes.
 */
export function updatePresetTextures(
  material: CustomShaderMaterial,
  textures: LoadedMaterialTextures,
): void;
```

**Auto-upgrade logic:** When `application.iridescence > 0`, `createPresetMaterial` uses `MeshPhysicalMaterial` as the CSM base and sets `iridescence`, `iridescenceIOR`, `iridescenceThicknessRange`. Otherwise it uses `MeshStandardMaterial` (cheaper shader). This applies to both projection modes.

**No `standardMaterial.ts` file.** Both triplanar and UV projection share the same CSM factory. The `onBeforeCompile` approach was rejected during review — it doesn't support per-frame uniform updates needed for animatable `MaterialApplication` controls.

**Dependency:** `three`, `three-custom-shader-material` (already in core's deps).

### 2.3 — KTX2 Conversion

Script: `packages/textures/scripts/convert-textures.sh`

Uses `toktx` from KTX-Software (`brew install ktx-software`).

Per-map encoding strategy:

| Map | Encoding | Rationale |
|---|---|---|
| Color | UASTC quality 3 + Zstandard supercompression | Visible map — quality matters |
| Normal | UASTC quality 3 + Zstandard, linear OETF | Compression artifacts on normals cause shading errors |
| Roughness | ETC1S clevel 4, linear OETF | Single-channel gradient — artifacts invisible |
| Displacement | ETC1S clevel 4, linear OETF | Low-frequency height data — artifacts invisible |

Expected sizes per preset:

| Map | KTX2 size |
|---|---|
| Color (UASTC) | ~1.0–1.5 MB |
| Normal (UASTC) | ~1.5–2.0 MB |
| Roughness (ETC1S) | ~200–400 KB |
| Displacement (ETC1S) | ~100–200 KB |
| **Per preset total** | **~3–4 MB** |
| **10 presets total** | **~30–40 MB** |
| Basis transcoder | ~500 KB |
| **Package total** | **~35–45 MB** |

```typescript
  transcoderPath?: string;
  /** Additional presets to register (merged into built-in manifest). */
  extraPresets?: Record<string, import('@brewsite/core').MaterialPreset>;
}

export function texturesPlugin(options: TexturesPluginOptions = {}): WidgetPlugin {
  const basePath = options.basePath ?? '/assets/materials';
  const transcoderPath = options.transcoderPath ?? `${basePath}/basis/`;

  // Captured during configureRegistry(), used by lifecycle hooks.
  let registryRef: WidgetRegistry | null = null;

  const manifest: MaterialManifest = {
    version: BUILTIN_MANIFEST.version,
    basePath,
    presets: {
      ...BUILTIN_MANIFEST.presets,
      ...options.extraPresets,
    },
  };

  return {
    createWidgets: () => [],
    registerHandlers: () => {},

    configureRegistry(registry: WidgetRegistry, _manifest: AssetManifest | null): void {
      registryRef = registry;
      registry.setMaterialManifest(manifest);
    },

    onRendererCreated(renderer) {
      if (!registryRef) return;
      const loader = registryRef.getMaterialLoader();
      loader.initialize(renderer, transcoderPath);
    },

    onRendererDisposing(renderer) {
      if (!registryRef) return;
      const loader = registryRef.getMaterialLoader();
      loader.disposeForRenderer(renderer);
    },
  };
}
```

### Bundle size note:

`MaterialLoader` is imported by widget `apply()` methods, so it is included in `@brewsite/core`'s bundle even when `@brewsite/textures` is not installed. The `MaterialLoader` class itself is lightweight — it only initializes `KTX2Loader` and creates `Texture` objects when `loadPreset()` is actually called. The heavy Basis transcoder WASM (~500 KB) is fetched at runtime only when the first texture is loaded. Consumers who never call `texturesPlugin()` pay only the class definition cost (~2 KB minified), not the transcoder or texture download cost.
